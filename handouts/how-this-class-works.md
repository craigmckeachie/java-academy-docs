# How This Class Works

## Why we changed things

After Week 1, your feedback showed the class was split:

- **Many of you liked working at your own pace**: lots of breakout time, trying things first, then asking for help.
- **Many of you wanted to *see* it before reading about it**: a demo first, an example walked through together, and no off-topic tangents.

Both are completely reasonable ways to learn, so the class now does **both** for every major topic.

## The rhythm: I Do → We Do → You Do

| Step | Time | What happens |
|---|---|---|
| **1. Demo** (I Do) | up to one 25-min pomodoro | A short, focused demo shows the new idea running in IntelliJ, often stepping through it in the debugger so you can watch it work. |
| **2. Bridge** (We Do) | last few minutes of that pomodoro | We connect the demo to the **exact workbook pages** and the **exercise** you'll do next. |
| **3. Breakouts** (You Do) | the following pomodoros | You read the rest of the section and work the exercises **at your own pace**. Your instructor moves between rooms to coach. |

**Demo first, then the reading.** Seeing it work first gives you a picture in your head, so the workbook makes more sense. The workbook is now your **lookup guide** while you do the exercises, not something you have to figure out alone.

## What the demos are like

- **One idea at a time.** Short demos, each focused on a single concept. No tangents.
- **Different examples from your exercises.** The demo teaches the same concept using a different scenario, so it doesn't give away your exercise. (A demo about a game scoreboard might teach the same methods you'll use in a calculator.)
- **Predict the output.** You'll sometimes be asked, *"What do you think this prints?"* Type your guess in the chat before we run it. Guessing wrong is part of learning.
- **Watching code run.** The debugger lets us pause the program and watch the values change, line by line.

### Demo code on GitHub

All demo code is in the **[java-academy-demos](https://github.com/craigmckeachie/java-academy-demos)** repository:

- Each file teaches **one concept** and is named for it, e.g. `methods/ParametersDemo.java`.
- The **starter** is posted before class. The **finished** version, with the **same name**, appears in a `solutions/` folder after class, e.g. `methods/solutions/ParametersDemo.java`.
- Clone it once, open it in IntelliJ, and run `git pull` each day to get the newest demos.
- Don't edit files in that project. Copy code into your own project to experiment.

## If you're stuck

- **Try for about 10 minutes first:** reread the workbook section and run your code.
- **Stuck on your own code?** The [Help Desk](./help-desk.md) is for getting unstuck. You share your screen and you type.
- **The topic didn't click?** That's normal. Ask your instructor to go over it with you again.
- **Ask early.** Being stuck is part of learning to code, and asking for help is a skill.

## Class norms

- **Use each other's names and pronouns.** Check display names, and if you're not sure of someone's pronouns, use *they/them*.
- **Helping is a choice.** You're welcome to help a classmate, and you never have to.
- **AI is a learning partner, not a ghostwriter.** Write your own attempt first, then use AI to explain or review it. You should be able to explain every line you submit. See the [AI Use Policy](./ai-use-policy.md).
- **Tell us how it's going.** We'll keep checking in through the Friday surveys and adjust.
